模拟仓库的规则

main 是当前本地分支，origin/main 是本地保存的远程跟踪分支，远程 main 是服务器上的实际分支。提交图同时展示两个仓库，虚线边框的提交目前只在远程可见。

你修改 README.md，同事只修改 notes.md。练习中的 pull --no-rebase 采用合并策略。历史能快进时只移动分支指针，历史分叉时创建一个双亲合并提交。模拟器要求暂存区和工作区都干净才整合远程变更，真实 Git 可保留部分互不冲突的工作区修改。

git restore --staged 把暂存区恢复为 HEAD 的版本，工作区的修改保留；git restore 用暂存区的版本覆盖工作区，未暂存的修改会丢失，真实使用时要谨慎。

可以试试先修改并暂存 README.md，再修改一次后提交。提交会使用暂存时的文件版本，较新的修改仍留在工作区。

开发期间 main 更新了

同事的 PR 先合并后，把最新 main 同步进你的分支。两种方式任选：

方法 A · merge安全 
git fetch origin
git merge origin/main
git push

不改写历史，会多一个合并提交。共享分支只能用这种。

方法 B · rebase仅限个人分支 
git fetch origin
git rebase origin/main
git push --force-with-lease

历史成一条直线。rebase 改写了提交，推送必须带 --force-with-lease。

PR 的三种合并方式

Merge commit

保留分支全部提交，外加一个双亲合并节点。历史完整，但图会比较乱。

Squash and merge

分支所有提交压成一个放到 main。main 最整洁，最常用。

Rebase and merge

提交逐个接到 main 后面，没有合并节点。适合提交写得规整的团队。

团队约定

  • 保护 main仓库设置中禁止直接推送，必须通过 PR，并至少 1 人审查通过。
  • PR 要小几百行以内，审查快、冲突少。一个 PR 只做一件事。
  • 勤同步分支活得越久，最后的冲突越大。每天开工前同步一次 main。
  • 不强推公共分支main 永远不 force push；个人分支用 --force-with-lease 而不是 --force。
  • 统一提交信息采用 feat: fix: docs: 等前缀（Conventional Commits）。
  • 合并后删分支避免分支越积越多，本地用 git fetch --prune 清理已删除的远程分支。

在 RStudio 中使用 Git

RStudio 的 Git 面板覆盖了日常的 add、commit、pull、push 和分支；更复杂的操作用内置终端或 usethis 包。

① 一次性配置

1
让 RStudio 找到 Git

先安装 Git。然后打开 Tools → Global Options → Git/SVN，勾选 Enable version control interface for RStudio projects，确认 Git executable 路径（Windows 通常是 C:/Program Files/Git/bin/git.exe），重启 RStudio。

2
设置提交身份 
install.packages(c("usethis", "gitcreds"))
usethis::use_git_config(user.name  = "你的名字",
                        user.email = "you@example.com")
3
配置 GitHub 凭据（二选一）

HTTPS + 令牌（推荐）：

usethis::create_github_token()   # 浏览器中生成 PAT 并复制
gitcreds::gitcreds_set()          # 粘贴令牌保存
usethis::git_sitrep()             # 体检：检查 Git 与 GitHub 配置

SSH：Global Options → Git/SVN → Create SSH Key，点 View public key 复制，粘贴到 GitHub → Settings → SSH keys。

② 把项目纳入 Git

从 GitHub 克隆已有仓库

File → New Project → Version Control → Git，填入仓库地址，选择本地目录，点 Create Project。相当于 git clone。

usethis::create_from_github("团队名/仓库名")  # 命令方式
已有的 R 项目开始用 Git

在项目中运行：

usethis::use_git()      # 初始化仓库并首次提交（会提示重启）
usethis::use_github()   # 在 GitHub 创建远程仓库并推送

分支与 PR：usethis 助手

面板右上角 ⑂ New Branch 创建分支（保持勾选 Sync branch with remote 会同时推送），旁边下拉框切换分支。完整的 PR 流程用 usethis 更省事：

pr_init("feature-x")从最新 main 创建并切换到新分支
pr_push()推送分支，并在浏览器打开创建 PR 的页面
pr_merge_main()把远程 main 的最新改动合并进当前分支
pr_fetch(12)把同事的 PR #12 拉到本地，方便审查或修改
pr_pause()暂时离开 PR 分支，回到 main
pr_finish()PR 在网页合并后，切回 main、拉取并删除本地分支

以上函数都在 usethis 包中，可写作 usethis::pr_init()。

在 RStudio 中解决冲突

  1. 点 Pull 后提示冲突，Git 面板中文件显示 U。
  2. 打开该文件，Ctrl+F 搜索 <<<<<<<，保留正确内容并删除三种标记行。
  3. 保存文件，在 Git 面板勾选 Staged。
  4. 点 Commit，提交说明已预填为 Merge 信息，直接提交。
  5. 点 Push 推送。想放弃本次合并：终端运行 git merge --abort。

Git 面板没有 stash、rebase、reset 等按钮，遇到这些操作请在 Terminal 中输入命令，命令和实验室、速查表里的完全一样。

R 项目的 .gitignore

.Rproj.user/
.Rhistory
.RData
.Ruserdata
.Renviron        # 可能含密钥，切勿提交
data/raw/        # 大数据文件不要放进 Git

用 usethis::use_git_ignore(c(".Renviron", "data/raw/")) 追加规则。若文件已被提交过，先 git rm --cached 文件 再忽略才会生效。

提示：用 renv 管理包版本时，提交 renv.lock，不要提交 renv/library/。
