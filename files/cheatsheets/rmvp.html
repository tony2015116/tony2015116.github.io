概览与标准流程

华中农业大学刘小磊团队 · Apache-2.0 · CRAN + GitHub

三步工作流

MVP.Data()格式转换 · 对齐表型 · 算 K / PC

数据准备：MVP.Data()

转换时一并提供表型，rMVP 自动对齐个体顺序

四种基因型格式

格式关键参数完整调用（推荐）仅转基因型 *
PLINK binaryfileBed（前缀，不含后缀）MVP.Data(fileBed="plink", filePhe=NULL, fileKin=FALSE, filePC=FALSE, out="mvp.plink")MVP.Data.Bfile2MVP(bfile="plink", out="mvp", maxLine=1e4)
VCFfileVCFMVP.Data(fileVCF="myVCF.vcf", fileKin=FALSE, filePC=FALSE, out="mvp.vcf")MVP.Data.VCF2MVP("myVCF.vcf", out="mvp")
HapMapfileHMP（可为向量）、sep.hmp、SNP.effect="Add"MVP.Data(fileHMP="hapmap.txt", filePhe="Phenotype.txt", sep.hmp="\t", sep.phe="\t", SNP.effect="Add", out="mvp.hmp")MVP.Data.Hapmap2MVP("hapmap.txt", out="mvp")
Numeric 0/1/2fileNum + fileMap、type.geno、auto_transposeMVP.Data(fileNum="Numeric.txt", filePhe="Phenotype.txt", fileMap="Map.txt", sep.num="\t", sep.map="\t", sep.phe="\t", out="mvp.num")MVP.Data.Numeric2MVP("Numeric.txt", out="mvp", maxLine=1e4, auto_transpose=TRUE)

* 仅转基因型的函数要求基因型已完全填充（无缺失）。HapMap 可按染色体给多个文件：fileHMP=c("chr1.hmp.txt","chr2.hmp.txt")

MVP.Data() 通用参数

参数含义
filePhe / sep.phe表型文件及分隔符
fileKinTRUE 计算亲缘矩阵；或给文件名读入外部 K
filePCTRUE 计算 PCA；或给文件名读入外部 PC
out输出文件前缀
maxLine每次读入内存的标记数，内存紧张时调小
type.genoNumeric："char" / "integer" / "double"
auto_transposeNumeric 自动转置，保证行 = 标记

输入文件长什么样

# 表型：ID + 每列一个性状，缺失写 NA，带表头
Taxa   trait1  trait2  trait3
33-16  101.5   0.25    0
4722   105.5   NA      0

# Map（Numeric 格式需要）：带表头三列
SNP        Chr  Pos
rs3683945  1    3197400

# Numeric：m×n 或 n×m 均可，值为 0/1/2

转换后生成的文件 out="mvp"

文件内容
mvp.geno.desc / .bin基因型 big.matrix
mvp.geno.map标记信息：SNP、CHROM、POS
mvp.geno.ind个体 ID（顺序基准）
mvp.phe已对齐的新表型文件
mvp.kin.desc / .bin亲缘矩阵（fileKin=TRUE）
mvp.pc.desc / .bin主成分（filePC=TRUE）

读入数据

genotype  <- attach.big.matrix("mvp.geno.desc")
phenotype <- read.table("mvp.phe", head=TRUE)
map       <- read.table("mvp.geno.map", head=TRUE)
注意　转换时给了表型，后续一定读新生成的 mvp.phe，不要读原始表型文件。
03

GWAS 主函数：MVP()

phe 只接受两列：ID + 一个性状

完整模板

imMVP <- MVP(
  phe = phenotype,          # 两列，可含 NA
  geno = genotype,
  map = map,
  #K = Kinship,             # 有预算好的 K 才打开
  #CV.GLM = Covariates,     # 有协变量时打开全部 CV.*
  #CV.MLM = Covariates,
  #CV.FarmCPU = Covariates,
  nPC.GLM = 5,              # 不加 PC：注释掉，别写 0
  nPC.MLM = 3,
  nPC.FarmCPU = 3,
  maxLine = 10000,          # 调小可降内存
  #ncpus = 10,              # 默认用全部 CPU
  vc.method = "BRENT",      # 仅 MLM
  method.bin = "static",    # 仅 FarmCPU
  threshold = 0.05,
  method = c("GLM", "MLM", "FarmCPU"),
  file.output = c("pmap", "pmap.signal", "plot", "log")
)

三条易错规则

1　不加 PC 时注释掉 nPC.*，不要写 nPC.* = 0。
2　nPC.* > 0 时，对应 CV.* 中不能再含 PC，否则重复加入。
3　rMVP 不会调整协变量的个体顺序，须与 mvp.geno.ind 一致。

阈值怎么定

  • threshold=0.05：显著线 = 0.05 / 标记数（Bonferroni）
  • permutation.threshold=TRUE + permutation.rep：打乱表型多次，取每次最小 p 值的 95% 分位数作经验阈值

参数速查

参数取值 / 示例说明
phedata.frame（2 列）表型：ID + 一个性状
genobig.matrixattach.big.matrix("mvp.geno.desc")
mapdata.frameSNP、染色体、位置
Kn×n 矩阵亲缘矩阵；不给则自动按 VanRaden 计算
CV.GLM / CV.MLM / CV.FarmCPUn×nCV 矩阵各模型协变量，可含 NA
nPC.GLM / nPC.MLM / nPC.FarmCPU整数，如 5 / 3 / 3作为协变量的前 n 个主成分
method"GLM", "MLM", "FarmCPU"可选一个或多个
vc.method"BRENT", "EMMA", "HE"MLM 方差组分估计方法
method.bin"static", "FaST-LMM"FarmCPU 的 bin 选择方法
maxLoop整数FarmCPU 最大迭代次数
threshold0.05显著线 = threshold / 标记数
permutation.thresholdTRUE / FALSE用置换检验定阈值
permutation.rep整数，如 100置换次数
maxLine10000每批处理标记数，越小越省内存
ncpus整数并行 CPU 数，默认全部
file.outputTRUE / FALSE 或子集"pmap" 全部 SNP · "pmap.signal" 显著 SNP · "plot" 图 · "log" 日志

亲缘矩阵、主成分与协变量

外部文件为纯数值：无个体名、无表头，行顺序同基因型

K 与 PC：读入或计算

# 亲缘矩阵（n×n）
MVP.Data.Kin("mvp.kin.txt", out="mvp", maxLine=1e4, sep="\t")  # 读文件
MVP.Data.Kin(TRUE, mvp_prefix="mvp.vcf", out="mvp")              # 计算

# 主成分（n×nPC）
MVP.Data.PC("mvp.pc.txt", out="mvp", sep="\t")                   # 读文件
MVP.Data.PC(TRUE, mvp_prefix="mvp.vcf", pcs.keep=5)             # 计算

# 加载
Kinship       <- attach.big.matrix("mvp.kin.desc")
Covariates_PC <- bigmemory::as.matrix(attach.big.matrix("mvp.pc.desc"))

环境因子 / 协变量

# 品种、性别作因子，体重作数值协变量
Covariates <- model.matrix.lm(
  ~ as.factor(breed) + as.factor(sex) + as.numeric(weight),
  data = yourdata, na.action = "na.pass")   # 允许 NA

# 把 PC 并入协变量（此时 MVP() 中不要设 nPC.*）
Covariates <- cbind(Covariates, Covariates_PC)
注意　yourdata 的行顺序必须与 mvp.geno.ind 一致。

可视化：MVP.Report()

约 50 个参数 · 也接受 PLINK / GEMMA / GAPIT / TASSEL 结果

plot.type

值图形输入
"d"SNP 密度图前 3 列即可
"c"环形曼哈顿图p 值或效应列
"m"矩形曼哈顿图p 值或效应列
"q"QQ 图p 值列

输入至少 4 列：SNP、染色体、位置、p 值；多性状继续按列追加。示例数据 data(pig60K)（MLM p 值）、data(cattle50K)（rrBLUP 效应）。

常用参数

参数作用
col向量按染色体交替；矩阵则每性状一行
LOG10TRUE 画 −log10(p)；画效应时 FALSE
ylim / ylab纵轴范围与标签
threshold可多条 c(1e-6,1e-4)；NULL 不画
threshold.col / .lty / .lwd阈值线颜色、线型、线宽
amplifyTRUE 放大显著点
signal.col / .cex / .pch显著点样式；col=NULL 保持原色
signal.line环形图穿圈标示线；NULL 不画
chr.den.col长度 >1 时画 SNP 密度条
bin.size / bin.max密度窗口（如 1e6）与上限
chr.labels染色体标签
multracks多性状分轨 + 合并图

cir.legend / .col / .cex环形图图例
band / cex染色体间距、点大小
conf.int.col / boxQQ 图置信区间颜色、边框
file.type / dpi / memo"jpg"(默认) "pdf" "tiff"；分辨率；文件名附加标记

输出结果解读

返回值为列表，各模型结果为 Effect / SE / P 三列

在 R 中查看结果

names(imMVP)              # map, glm.results, mlm.results, farmcpu.results
head(imMVP$mlm.results)   # Effect, SE, P

# 拼出完整表并按 p 值排序
res <- cbind(imMVP$map, imMVP$mlm.results)
res <- res[order(res[, ncol(res)]), ]
head(res, 20)

# 用返回值重画
MVP.Report(imMVP, plot.type="m", threshold=0.05/nrow(map))

结果怎么看

  • 显著性：默认阈值 0.05 / 标记数；样本或标记高度连锁时，可用置换阈值替代过严的 Bonferroni。
  • QQ 图：多数点贴近对角线、尾部上翘为理想；整体抬升提示膨胀，可增加 PC 或改用 MLM / FarmCPU。
  • 模型对比：GLM 信号最多但假阳性多；MLM 最保守；FarmCPU 介于两者之间，峰更尖。

进阶用法

多性状 · 内存与速度 · 底层函数

多性状批量

for (i in 2:ncol(phenotype)) {
  imMVP <- MVP(phe = phenotype[, c(1, i)],
               geno = genotype, map = map,
               nPC.GLM = 5, nPC.MLM = 3, nPC.FarmCPU = 3,
               maxLine = 10000, vc.method = "BRENT",
               method.bin = "static", threshold = 0.05,
               method = c("GLM", "MLM", "FarmCPU"),
               file.output = c("pmap", "pmap.signal", "plot", "log"))
  gc()   # 每轮释放内存
}
提速　多性状共用一套 K / PC 时，先在 MVP.Data(..., fileKin=TRUE, filePC=TRUE) 中算好，再用 K= 传入。

内存与速度

目标做法
降内存调小 maxLine（5000 或 2000）
控 CPU设 ncpus，集群上避免占满节点
提速链接 MKL / OpenBLAS；复用 K 与 PC
少跑模型method = "MLM"
只要结果表file.output = c("pmap","pmap.signal")

前三条来自官方 FAQ

症状可能原因解决办法
